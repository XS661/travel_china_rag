
# 项目二 面向特定领域的智能知识问答系统设计与实现

指导老师：何希僖

## 一、项目简介

随着人工智能技术的发展，智能问答系统已经广泛应用于医疗健康、法律咨询、教育辅导、运动健身、金融反诈、校园服务等多个领域。与通用搜索引擎相比，面向特定领域的智能问答系统可以围绕明确的应用场景组织知识资源，结合信息检索、自然语言处理和大语言模型等技术，为用户提供更加聚焦、可解释、可追溯的问答服务。

本项目要求各小组自选一个具有实际应用价值的垂直领域，收集并整理该领域的文本资料，构建领域知识库，设计并实现一个支持自然语言提问的智能知识问答系统。你们需要让系统能够根据用户问题检索相关资料，生成或组织回答内容，并展示答案来源，完成从数据收集、知识库构建、问答流程设计到软件系统实现的完整应用开发过程。

本项目重点考查人工智能应用系统的设计与实现能力，不要求进行复杂模型训练。你们可以使用关键词检索、向量检索、预训练模型、大语言模型 API 或本地轻量模型等方式完成系统功能。项目鼓励大家关注具体领域中的真实用户需求，做出具有实用性、可展示性和一定创新性的智能问答应用。各小组可自选领域，以下方向仅作为参考：

1. 眼底疾病健康科普问答系统：面向糖尿病视网膜病变、青光眼、黄斑病变等眼底疾病，提供疾病知识、检查项目、常见症状和就医建议说明。
2. 劳动法智能咨询助手：面向劳动合同、试用期、加班工资、社保缴纳、离职补偿、劳动仲裁等问题，提供法规条文查询和案例解释。
3. 运动健身智能建议系统：面向减脂、增肌、跑步训练、力量训练、运动损伤预防等场景，提供训练知识、动作说明和计划建议。
4. 校园生活智能助手：面向选课、请假、奖学金、宿舍管理、竞赛报名、校园服务流程等问题，提供校园事务问答。
5. 金融反诈知识问答系统：面向电信诈骗、网络贷款诈骗、刷单诈骗、投资骗局等场景，提供风险识别和防范建议。
6. 食品安全与营养问答系统：面向食品添加剂、过敏原、营养成分、特殊人群饮食等问题，提供科普知识查询。
7. 旅游出行问答与推荐系统：面向某一城市或景区，提供景点介绍、路线规划、美食推荐、预算建议和注意事项。
8. 宠物饲养知识助手：面向猫狗喂养、疫苗接种、常见疾病、行为训练等问题，提供饲养知识问答。

如果选择医疗、法律、心理健康、金融等具有较高风险的领域，必须在系统中明确说明：系统结果仅用于知识科普或辅助参考，不能替代专业医生、律师、心理咨询师或金融从业人员的判断。

## 二、基本要求

**1、领域选择与需求分析**

- 以 4 人为一组，自选一个具体应用领域，并说明选择该领域的原因。
- 所选领域需要具有明确用户群体、典型使用场景和可收集的知识资料。
- 分析系统的主要用户需求，至少给出 5 个典型问题示例。
- 明确系统边界，说明系统能回答什么问题，不能回答什么问题。
- 如果选择医疗、法律、金融、心理等特殊领域，需要说明系统的风险提示和使用限制。

**2、资料收集与知识库构建**

- 收集与所选领域相关的文本资料，可包括政策法规、专业指南、科普文章、说明手册、公开案例、FAQ、教材资料或公开数据集等。
- 资料来源需要尽量可靠，并在报告中列出来源。
- 对收集到的资料进行整理和预处理，包括文本清洗、格式转换、去重、分段、关键词提取等。
- 构建领域知识库。知识库中每条知识至少需要包含正文内容和来源信息，建议包含标题、类别、文档名称、段落编号、链接或出处等字段。
- 知识库规模需要与项目难度相匹配，建议不少于 30 条知识片段或不少于 1 万字领域资料。

**3、问答算法与流程设计**

- 设计系统的问答流程，包括用户输入、问题处理、知识检索、答案生成、结果展示等环节。
- **实现传统知识检索方案。至少从关键词匹配、TF-IDF、BM25、文本向量相似度检索等方法中选择 2 种进行实现，并对不同检索方法的效果进行简单比较。**
- **必须实现基于大语言模型的 RAG 问答方案，即先根据用户问题从知识库中检索相关内容，再将检索结果和用户问题一起提供给大语言模型，由大语言模型生成自然语言回答。**
- 不要求从头训练或自行搭建大语言模型。可以调用现有大语言模型 API，也可以使用本地已部署的开源大语言模型。
- 系统需要能够根据用户问题检索相关知识内容，并将检索结果作为大语言模型生成回答的主要依据。
- 设计基本提示词模板，要求模型尽量依据知识库内容回答问题，不能脱离检索资料随意生成。
- 答案中需要展示参考来源，便于用户追溯回答依据。
- 对无法回答的问题，系统需要给出合理提示，而不是编造答案。
- 在报告中说明所使用的大语言模型来源、调用方式、提示词设计和安全限制。

**4、软件系统设计与实现**

- 设计并实现一个可运行的软件系统，可采用 Web 应用、桌面应用或小程序等形式。
- 系统至少需要包含用户提问界面、答案展示界面和知识来源展示功能。
- 系统需要支持知识库数据的读取和问答流程调用。
- 系统需要具有基本的异常处理能力，例如空问题、无检索结果、文件读取失败、模型调用失败等情况。
- 系统界面需要清晰易用，能够支持课堂展示和答辩演示。
- 鼓励实现用户登录、问答历史、知识库管理、资料上传、领域分类筛选等功能。

**5、系统测试与结果分析**

- 设计测试问题集，测试问题需要覆盖所选领域的主要应用场景。
- 至少选取 10 个问题进行系统测试，并记录系统回答结果。
- 分析系统回答的准确性、完整性、可追溯性和不足之处。
- 对检索效果进行简单评价，可统计命中率、相关性等。
- 分析系统在资料不足、问题模糊、跨领域问题等情况下的表现。

**6、项目展示与报告撰写**

- 完成项目演示，展示系统的主要功能、技术路线、典型问答效果和小组分工。
- 提交项目源代码、运行说明、知识库资料、测试结果和项目总结报告。
- 报告中需要说明项目开发过程中遇到的问题、解决方案和改进方向。
- 报告中引用的资料、代码、模型、开源项目或网站需要列入参考文献。

## 三、选做要求

**1、大模型问答能力增强**

- 优化提示词模板，使模型回答更加符合领域要求。
- 支持多轮对话，能够结合上下文进行追问。
- 对答案进行结构化展示，例如分点说明、风险提示、操作步骤、推荐理由等。
- 对回答进行可信度提示或相关资料数量提示。
- 支持对模型回答进行二次校验，例如检查回答是否引用了知识库资料、是否出现无依据内容。

**2、知识库管理功能**

- 支持用户上传 PDF、Word、TXT 等格式文件，并自动解析入库。
- 支持管理员新增、修改、删除知识条目。
- 支持知识分类、标签管理和关键词搜索。
- 支持知识库更新后重新建立索引。

**3、检索与评价优化**

- 同时实现关键词检索和向量检索，并比较两种方法的效果。
- 引入文本重排序方法，提高检索结果相关性。
- 设计问答评价指标，对不同方案进行对比实验。
- 对系统无法回答的问题进行记录，用于后续改进知识库。

**4、特色应用功能**

- 医疗健康类项目可增加症状科普、检查项目解释、就医科室建议和风险提示。
- 法律类项目可增加法规条文查询、案例检索、流程指引和材料清单生成。
- 运动健身类项目可增加训练计划生成、运动记录分析、动作注意事项和禁忌提示。
- 旅游类项目可增加路线规划、预算估算、景点推荐和行程安排。
- 校园服务类项目可增加办事流程导航、通知查询和常见问题管理。

**5、系统工程完善**

- 使用数据库保存用户、知识库和问答历史。
- 提供清晰的安装部署说明。
- 增加系统日志和错误提示。
- 对界面进行优化，提高系统易用性和展示效果。
- 部署为可访问的 Web 服务。

1. 项目源代码及运行说明。（包含知识库原始资料和处理后的知识库文件。）
2. 项目总结报告。
3. 项目展示 PPT。（包含系统运行截图或演示视频，小组成员分工说明）

# 附录一：实现方案指导

本附录给出若干可选实现方案。各小组可根据自身基础、设备条件和项目目标选择合适路线，也可以在此基础上进行调整。

## 1、基础方案：关键词检索式问答系统

该方案实现难度较低，适合希望先完成系统闭环的小组。基本流程如下：

用户输入问题
↓
问题分词和关键词提取
↓
在知识库中进行关键词匹配
↓
按照匹配数量或权重排序
↓
返回最相关知识片段
↓
调用大语言模型生成回答
↓
展示回答和资料来源

可选技术：

- Python
- Flask 或 FastAPI
- jieba 分词
- SQLite 或 JSON 文件
- HTML、CSS、JavaScript
- 大语言模型 API 或本地大语言模型

该方案实现简单、可解释性强、无需模型训练，适合快速完成"知识检索 + 大模型回答"的基本流程，但对同义词、长问题和复杂表达的理解能力较弱。

## 2、进阶方案：TF-IDF 或 BM25 检索问答系统

如果希望体现一定算法设计，可以选择该方案。基本流程如下：

知识库文本向量化
↓
用户问题向量化
↓
计算问题与知识片段的相似度
↓
返回相似度最高的若干条知识
↓
调用大语言模型生成答案
↓
展示答案和资料来源

可选技术：

- scikit-learn 的 TfidfVectorizer
- rank-bm25
- jieba
- Flask 或 FastAPI
- SQLite、CSV 或 JSON
- 大语言模型 API 或本地大语言模型

该方案无需训练深度模型，但比简单关键词匹配更稳定，适合作为本项目的推荐基础方案。

## 3、提高方案：向量检索问答系统

该方案使用预训练文本向量模型，将问题和知识片段映射到向量空间中，通过相似度计算找到相关知识。基本流程如下：

领域资料分段
↓
使用预训练模型生成文本向量
↓
建立向量索引
↓
用户问题生成向量
↓
向量相似度检索
↓
返回相关知识片段和来源
↓
调用大语言模型生成答案
↓
展示答案和资料来源

可选技术：

- sentence-transformers
- FAISS
- Chroma
- SQLite
- Flask、FastAPI 或 Streamlit
- 大语言模型 API 或本地大语言模型

该方案不需要自行训练模型，适合实现语义检索。例如用户问"被公司辞退有没有赔偿"，系统也能检索到"解除劳动合同经济补偿"的相关资料。

## 4、扩展方案：RAG 智能问答系统

RAG 即检索增强生成，是目前智能知识问答系统中常见的技术路线。你们可以先从知识库中检索相关内容，再将检索结果和用户问题一起发送给大语言模型，由模型生成自然语言答案。基本流程如下：

用户问题
↓
知识库检索
↓
选取 Top-K 相关片段
↓
构造提示词
↓
调用大语言模型
↓
生成答案
↓
展示答案和引用来源

**提示词示例：**

你是一个面向特定领域的知识问答助手。请只根据给定资料回答用户问题。
如果资料中没有足够信息，请回答"根据当前知识库无法确定"，不要编造。

【资料】
{检索到的知识片段}

【用户问题】
{用户问题}

请给出简洁、准确、分点说明的回答，并标注参考资料编号。

**注意事项：**

- 不要直接让模型凭空回答，尽量要求模型基于知识库内容回答。
- 保留检索到的资料来源，方便用户查看。
- 对医疗、法律、金融等领域，需要加入免责声明。
- 如果使用外部 API，需要注意密钥安全，不要将 API Key 写入公开代码。

## 7、测试问题设计参考

测试问题需要覆盖不同类型：

- 事实查询类：某个概念是什么？
- 流程说明类：遇到某种情况应该怎么处理？
- 对比分析类：两个概念有什么区别？
- 建议生成类：根据某个条件给出建议。
- 边界问题类：知识库中没有答案的问题。

示例：

- 劳动法方向：试用期内被辞退有补偿吗？
- 眼底疾病方向：糖尿病为什么需要定期检查眼底？
- 运动健身方向：新手增肌训练一周几次比较合适？
- 金融反诈方向：刷单返利为什么可能是诈骗？
- 校园服务方向：申请奖学金一般需要准备哪些材料？
